# 움짤 서랍

iPhone 등 모바일 브라우저에서 쓰는 **개인용 움짤(애니메이션 WebP) 서랍**입니다. 파일을 한 번 담아 두면 브라우저 안(IndexedDB)에 남아, 다음부터는 고를 필요 없이 바로 열어 볼 수 있습니다. 빌드 과정 없이 정적 HTML 파일만으로 동작합니다.

## 주요 기능

- **파일 담기** — WebP·GIF·APNG·PNG·AVIF를 여러 장 한꺼번에 담을 수 있고, 드래그 앤 드롭도 지원합니다.
- **격자 보기** — 3열(좁은 화면) → 4열 → 6열로 늘어나는 썸네일 격자와 파일 개수 표시.
- **뷰어** — 좌우 스와이프·방향키·이전/다음 버튼으로 넘겨 보고, 처음부터 다시 재생하거나 공유(Web Share)할 수 있습니다.
- **편집 모드** — 여러 장을 골라 삭제합니다.
- **정보** — 서랍 정보 시트.
- **홈 화면 추가** — `apple-mobile-web-app-*` 메타와 아이콘이 들어 있어 PWA처럼 설치해 쓸 수 있습니다.

## 애니메이션 WebP 재생 방식

브라우저의 `<img>`로 큰 애니메이션 WebP를 재생하면 뒤로 갈수록 끊기는 문제가 있어(프레임 N을 그리려면 0..N을 다시 디코딩해야 함), 프레임 타이밍을 브라우저에 맡기지 않고 직접 재생합니다.

1. RIFF 컨테이너를 직접 파싱해 ANMF 프레임을 분리합니다 (`parseWebPAnim`).
2. 가능하면 **WebCodecs `ImageDecoder`**(플랫폼 디코더)를 우선 사용합니다.
3. 없으면 각 하위 프레임을 정지 WebP로 감싸 `createImageBitmap`으로 디코딩하고, 하나의 캔버스에 앞으로만 합성합니다. 프레임당 비용이 인덱스와 무관하게 일정합니다.
4. 프레임은 미리 캐시(약 96MB 상한)하거나 12프레임 앞서 읽는 링 버퍼로 준비합니다.

애니메이션이 아닌 파일은 일반 `<img>`로 보여 줍니다.

## 움짤 진단 (`diag.html`)

특정 WebP가 이 기기에서 왜 느린지 측정하는 도구입니다. 문제가 되는 파일을 고르면 디코딩 시간 등을 재고, 결과를 복사해서 공유할 수 있습니다.

## 구성

| 파일 | 설명 |
| --- | --- |
| `index.html` | 앱 전체 (HTML + CSS + JS 한 파일) |
| `diag.html` | WebP 재생 진단 도구 |

## 실행

정적 파일이므로 어떤 정적 서버로 열어도 됩니다.

```bash
python3 -m http.server 8000
# http://localhost:8000/ (앱), http://localhost:8000/diag.html (진단)
```

GitHub Pages 등에 그대로 올려도 됩니다. 담은 파일은 서버로 전송되지 않고 해당 브라우저의 IndexedDB(`webp-shelf`)에만 저장되므로, 브라우저 데이터를 지우면 함께 사라집니다.
